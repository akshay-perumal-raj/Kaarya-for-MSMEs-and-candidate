# CNC_LAB

## Practical Skill Verification Engine

> **Don't just claim the skill. Prove it.**

CNC_LAB is an interactive, browser-based **practical skill verification and workforce-readiness prototype for CNC machining**.

The platform is designed around a simple premise:

**A resume can claim that someone knows CNC machining. A practical simulation can test whether they actually do.**

CNC_LAB combines an interactive CNC turning workstation, configurable machining parameters, process-sequence selection, simulated machining, performance evaluation, targeted micro-learning, reassessment, and an employer-facing verification dashboard into a single prototype application.

The current implementation is a React-based single-page application written in TSX. It is designed as a functional proof-of-concept for demonstrating how practical manufacturing skills can be assessed digitally and converted into a structured, employer-readable verification record.

# Overview

CNC_LAB is a prototype platform for **digital practical-skill verification in manufacturing**.

Traditional hiring and training systems frequently depend on:

* resumes,
* certificates,
* self-reported skills,
* theoretical examinations,
* interviews,
* or subjective assessments.

These approaches do not always answer the most important question:

> **Can the candidate actually perform the required operation correctly?**

CNC_LAB approaches the problem through a simulated practical workstation.

A candidate is presented with a CNC turning task and must configure machining parameters and execute a simulated machining cycle. The system then produces an assessment outcome and identifies areas requiring improvement.

The candidate can subsequently complete targeted learning and undergo reassessment.

The employer portal provides a simplified view of the candidate's verification status and practical-skill audit.

---

# Problem Statement

## The Manufacturing Skills Verification Problem

Manufacturing employers, particularly MSMEs, often need skilled CNC operators and machinists but may face difficulties in reliably evaluating candidates before employment.

A candidate may claim proficiency in:

* CNC operation,
* turning,
* tool selection,
* feed-rate selection,
* spindle-speed selection,
* process planning,
* finishing operations,
* GD&T,
* measurement,
* or machining practices.

However, certificates and resumes alone cannot guarantee practical competence.

This creates several problems:

### For candidates

* Skills may be difficult to demonstrate before employment.
* Lack of formal practical credentials can reduce employability.
* Candidates may know the theory but lack confidence in practical application.
* Training gaps may remain unidentified.

### For employers

* Hiring decisions can depend heavily on interviews and resumes.
* Practical skill verification can require physical machines and supervisors.
* Testing candidates on production equipment can be expensive or risky.
* Skill gaps may only become visible after hiring.

### For training institutions

* Practical assessments can be difficult to standardize.
* Individual instructors may evaluate candidates differently.
* Training outcomes may not translate cleanly into employer-readable evidence.

CNC_LAB attempts to create a digital bridge between **training, assessment, verification, and hiring**.

---

# Solution

CNC_LAB provides an interactive environment where a candidate can:

1. Enter a virtual CNC workstation.
2. Select a machining tool.
3. Configure spindle speed.
4. Configure feed rate.
5. Configure depth of cut.
6. Define the machining process sequence.
7. Run a simulated CNC cycle.
8. Observe the machining operation visually.
9. Receive a practical assessment result.
10. Review identified skill gaps.
11. Complete targeted micro-learning.
12. Receive a post-training score.
13. Become eligible for employer shortlisting.

The employer can then:

1. Access the MSME Owner Portal.
2. View the candidate pipeline.
3. Inspect the candidate's practical-skill audit.
4. Compare initial and post-training performance.
5. Determine whether required capabilities have been verified.
6. Shortlist the candidate when the required status has been achieved.

The current prototype implements this entire journey as a front-end simulation.

Conceptually:

```text
App
│
├── Global State
│
├── Theme Management
│
├── Navigation History
│
├── Candidate Data
│
├── HomeView
│
├── CandidateDashView
│
├── AssessmentView
│
├── ResultsView
│
├── LearningView
│
├── MSMEDashView
│
└── MSMEReportView
```

The application uses a state variable called:

```text
view
```

to determine which interface should be displayed.

Current views include:

```text
HOME
CANDIDATE_DASH
ASSESSMENT
RESULTS
LEARNING
MSME_DASH
MSME_REPORT
```

# Current Prototype Limitations

CNC_LAB is currently a **front-end proof-of-concept**.

It should not yet be represented as a production-grade CNC training or certification platform.

## 1. No backend

The current application does not have a production backend.

Candidate information is stored in React state.

Refreshing the browser resets the application state.

---

## 2. No authentication

There is currently no:

* candidate login,
* employer login,
* administrator login,
* OAuth,
* role-based access control,
* password management.

---

## 3. No database

There is currently no persistent:

* candidate database,
* assessment database,
* employer database,
* training history,
* certification history,
* audit trail.

---

## 4. Simulated assessment

The CNC machining process is a browser visualization.

It is not connected to:

* a physical CNC machine,
* machine PLC,
* CNC controller,
* industrial sensor system,
* machine telemetry,
* actual spindle feedback,
* actual cutting-force measurements.

---

## 5. Prototype scoring

The current assessment result is predetermined for demonstration purposes.

The score should therefore be treated as:

```text
DEMO / PROTOTYPE OUTPUT
```

rather than an independently validated competency score.

---

## 6. Learning video placeholder

The current learning module contains a placeholder for instructional video content.

A production implementation should connect this to an actual learning-content system or secure video delivery platform.

---

## 7. Employer shortlist action

The shortlist interface demonstrates the intended workflow but does not currently write the decision to a persistent employer database.

---

# Security Considerations

A production implementation should introduce a comprehensive security architecture.

Recommended requirements include:

* HTTPS everywhere
* secure authentication
* role-based authorization
* encrypted database storage
* server-side validation
* session management
* audit logging
* rate limiting
* secure API design
* CSRF protection where applicable
* secure password hashing
* privacy controls
* candidate consent mechanisms
* employer authorization
* data-retention policies

Candidate assessment records should not be stored exclusively in browser state in a production environment.
